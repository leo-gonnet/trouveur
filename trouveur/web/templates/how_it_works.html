How it works

Two halves that share only the database. Ingest builds one corpus for everyone; match selects from it for each user.

Boards are swept by their own structure, never with a user's keywords, so a job the user would have wanted but never thought to type still arrives. Every derived table is a pure, versioned function of the raw archive: bump the version and every row is recomputed from it, by the same worker that handles new postings. What can be recommended is bounded by age as well as by whether the posting is still open: only the last seven days are embedded, kept in the index and searched, so a vacancy that has gone cold leaves the index instead of competing in it.

A day's matching is published as an edition: one page per day, keyed on when a posting became a recommendation for this user rather than on when it was posted, and never rewritten afterwards. Two processes share the database and nothing else: the web app reads and enqueues, the runner sweeps, drains and matches. Either can be down without breaking the other.
